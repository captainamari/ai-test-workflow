# Prompt 4 — Adapt to an existing framework

这是一次公司测试框架接入任务。用户会指定测试仓库、隔离环境、一个业务操作、可修改目录和维护人员确认过的样本脚本。先读取这些资料与本次 inputs，不要调用真实业务接口。

产出接入表：逐项列出前置构造、业务调用、状态观察、记录查询、清理、身份获取、结果汇报对应的真实函数、参数、返回值、来源文件，以及缺失能力。区分 SDK 的客户端校验和服务端校验入口。未找到的函数保留为缺口，不根据命名规律编造。

检查当前 cases 格式能否表达目标领域。不能表达时，提出最小字段调整，并同时列出 validator、代码模板、adapter 和回归用例的修改；不要把其他业务强行塞入库存字段。需求中的异步等待、跨接口流程和并发行为分别设计，不在当前同步模板里偷偷增加 sleep 或无限重试。

先提交接入表和一条代表剧本的实现方案供维护人员确认。确认后，只在授权目录实现 adapter 与模板；复用现有基类、fixture、鉴权入口和清理机制。代码生成只填写确认过的调用、参数与断言，不修改测试发现和结果汇总规则。认证信息从项目已有配置入口获取，不写入提示词、样本或生成文件。

静态检查后，给出发现的测试列表及将创建和清理的资源。只有用户已指定可执行的隔离环境与范围时才运行；保存原始响应中的必要诊断字段并按项目约定脱敏。用一个正常场景和一个明确失败场景核实 adapter 的语义，再运行整个试点集合。报告实际执行范围及仍被阻塞的场景，不声称已经支持其他业务域。
