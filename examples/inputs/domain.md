# 领域与测试约定

商品拥有可用库存。预留记录包含商品、数量、请求编号和服务端生成的预留编号。创建测试商品与删除测试商品是测试辅助能力，不是被测业务。

每个测试创建独立商品，并在创建后立即登记清理。请求编号按每条测试的运行命名空间隔离；同一测试中的相同 key 必须转换为相同请求编号。

本地接口同步完成库存和预留记录更新，查询可以立即观察结果。迁移到异步系统时必须按业务约定增加有截止时间的轮询，不能直接复用此立即查询假设。

预留接口的 HTTP 200 表示请求被处理，业务结果由 code 表达。仅断言 HTTP 200 无法验证预留成功。负向测试必须保留 quantity 的原始类型和值，不让 SDK 自动转换。

初始库存是非负整数。预期库存和预留条数要从需求推导，不能从本轮被测结果反填。
